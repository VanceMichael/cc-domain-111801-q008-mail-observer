# MailObserver 来源约定

此服务管理共享邮箱的会话观察、成员与标记解释及报关交接清单。业务只采集同事目前能确认的工作状态：不下载附件、不代发邮件。

## 文件夹目录

目录请求为 `GET /mail/{文件夹}`（常规业务为 `GET /mail/INBOX`），返回 `mailbox`、可选的会话资料位置 `relation` 与 `messages`。每个目录成员以 `id`、`href` 提供来源身份与原文位置，原文中的 `message` 和 `mailbox` 必须与目录一致。

```json
{
  "mailbox": "INBOX",
  "relation": "/mail/INBOX/relations",
  "messages": [
    { "id": "M100", "href": "/mail/INBOX/records/M100" }
  ]
}
```

## 记录含义

```json
{
  "message": "M100",
  "mailbox": "INBOX",
  "uid": "100",
  "subject": "货票资料",
  "flags": ["pending"],
  "sender": "partner@local.invalid"
}
```

这里的字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。领域解释保留文件夹选择、稳定邮件编号、工作标记清单。工作标记 `pending` 表达“待补资料”，`handed` 表达“已移交”；没有标记的成员保留为未标记，不替同事推断状态。

`uid` 是文件夹内的稳定邮件编号；删除邮件后目录中的顺序位置会重排，因此顺序位置不能作为身份，更不能把新顺序号位置上的正文接到原来的邮件上。稳定身份只在所属邮箱代际（`epoch`）内成立。

## 会话变更资料与补查

目录通过 `relation` 声明会话资料位置：

```json
{
  "mailbox": "INBOX",
  "epoch": "E1",
  "sequence": 2,
  "window": [1, 2],
  "changes": [
    { "kind": "arrive", "sequence": 1, "id": "M100", "uid": "100" },
    { "kind": "expunge", "sequence": 2, "id": "M101", "uid": "101" }
  ]
}
```

- `epoch` 是邮箱代际。代际变化后旧代际的成员身份不能复活，必须重新确认整个文件夹的成员和标记。
- `sequence` 是来源当前顺序号，`window` 是来源仍能补发的顺序号区间。本地会话游标落在窗口之前时，中间变更已无法补发，同样触发重新确认，并在缺口记录中保留先前观察到哪一步（代际、顺序号、来源位置与观察时间）。
- `changes` 顺序号必须连续且不重复，类型为 `arrive`、`flags`、`move`、`expunge`。
- 支持补查的资料接受 `?since={顺序号}`，只返回该顺序号之后的变更，但 `epoch`、当前 `sequence` 与 `window` 仍完整声明。MailObserver 每轮带上本地已确认的游标持续接收。
- 目录不承诺所有会话资料与当前目录同时发布；HTTP 404、403、503 不能自行解释为业务删除，先记入缺口再按当前目录核对。

## 消失、迟到原文与移动关系

- 成员从目录消失且会话给出 `expunge` 或 `move` 依据时，记为“观察中消失”；其中仍带 `pending` 的成员属于“消失而未收齐的资料”。
- 已证实消失的成员之后又读到原文（迟到的会话回复或摘要），只记为迟到原文并保留在消失分类中，不能当成新来的待补资料，也不能复活该成员。
- 目录列出但原文没有读到的成员保留在“未读到”分类，不能为了对齐数量记成已移交。
- 移动认定必须两端依据齐备：来源端观察到消失，目标文件夹当前存在同一稳定身份（同代际）；`move` 变更的目标与目标文件夹一致时依据更强。仅主题相同最多列为“可能的移动关系”；跨代际身份不能对齐，也只能存疑。
- 目录不再列出、又缺少会话消失依据的成员进入“无法确认的缺口”，等待人工核对。

## 本地合作源

`fixtures/source.json` 的 `resources` 是本地来源的 URL 路径到响应正文的映射；只绑定回环地址，不连接真实监管、银行或合作方。`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟、`replace` 更新资源以及带 `supportsSince` 的会话补查；访问记录保留实际请求路径与查询参数，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。

## 原文和收件

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录与决策，并额外持久化会话观察依据（`sessions`）、代际成员状态（`members`）与无法确认的缺口（`gaps`）。收件业务键包含文件夹、代际与稳定编号，删除后到达的新邮件不会覆盖旧成员的依据。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。
